2.そもそもAIって何ができるの？

この章の目的：AIに詳しくない方向け。「AIって結局何なの？」を3つだけ覚えれば後は読めます。

たくさん種類がありますが、僕が日常で使っている AI（ChatGPT、Claude などが代表）は、ざっくり言うと「文章を読んで、文章で返してくれる、めちゃくちゃ物知りな相棒」です。
技術的には LLM（大規模言語モデル）＝大量の文章を学習して、次に来そうな言葉を予測する仕組み、と呼ばれます。

AIができる3つのこと（ざっくり）

できること具体例
① 作業の代行 長い文章の要約／メールの下書き／表の整理／コードを書く／検索して答えをまとめる
② 壁打ち相手 悩み・アイデア・企画を投げると、別の角度で意見が返ってくる。「批判してみて」「逆の立場で」も注文可
③ 自分を覚えてもらう 自分の好み・経歴・判断軸を毎回読ませることで、"自分専属の相棒"として動かせる

僕の使い方は、①→②→③ の順に「だんだん深く付き合っている」状態です。
次の章で、なんでそこまで使い倒すのか、を話します。

3.僕がAIを"使い倒している"理由

この章の目的：「便利だから」じゃなくて、もっと切実な事情があります。

同時に走らせている5つの仕事

  1. 俳優キャリア（オーディション・公演・稽古）
  2. note執筆（公開248本）
  3. 舞台台本制作（ハートフルコメディ路線）
  4. 国家試験対策（医学部5年・残り500日）
  5. Webサイト制作（個人サイト・依頼）

優先順位は決めてあります（俳優1→note→舞台→国試→Web）。
起きてる時間に全部を進めようとすると、どこかは当然止まる。だから AI に「止まる場所」を最小化してもらっています。

AIなし時代の僕の1日

  • 「今日のネタどうしよう…」と、ただ悩む時間が長かった
  • 過去記事を探すのに時間がかかる
  • リサーチも、ぜんぶ自分で抱える
  • 身体・稽古・勉強に、時間が回りきらない

AIあり（現在）の僕の1日

  • 「今日のネタどうしよう」を AI と話しながら、早めに抜けられる
  • 過去記事の参照は 自動（AIが探してくる）
  • リサーチは AI が事前にまとめる
  • 朝、Mac を開く前に "今日の提案" が LINE に届く
  • 俳優活動・体づくり・国試に、時間を回せる
  • 「考える時間」が残る
同じ30分でも、深さも量も、体感で10倍違う。

つまり、AIは「楽するため」じゃなくて、「本当に大事な活動（俳優・身体・対人関係）に、自分の時間を返してもらうため」に使っています。
その先に何を目指してるかは、セクション11（3年後の地図）で話します。

5.自動化の線引き：声の領域は本人を外さない、事務の領域は本人を外す NEW

この章の目的：僕がAI活用でいちばん語りたい、たった1つの線引き。
2026年9月の勉強会でも、いろいろ見せたいものはあったけれど、一番はここだと話しました。

きっかけ：目的が真逆の人に出会った

2026年6月、株式会社ヌーのさいとうひでおさんの note「Claude Code課金してから3週間。MAXプランの契約に至りました。会社の自動化インフラを全部公開します」を読みました。
僕と同じ Claude Code、同じ Max プランで、会社の仕組みを7つ自動化して、その中身を全部公開している記事です。

読んで最初に思ったのは「すごい」。次に思ったのは、「目的が真逆だ」でした。
さいとうさんの自動化は、記事を書くところまで含めて「本人を作業から外す」方向に振り切っている（と僕は読みました）。僕は、note・ジャーナリング・芝居に関しては、本人を外した瞬間に価値が消える。
同じ道具、同じ料金プランでも、領域によって自動化の目的が逆になる。それが、この線引きの出発点です。

2つの領域

🎤 声の領域🗂 事務の領域
何が入るか note、ジャーナリング、芝居、本人の内省 リサーチ、営業資料、収支の把握、同期やバックアップ、ネタ発掘、文字起こし、日程調整、公開後の事後処理
本人が消えたら 価値も消える 誰がやっても同じ
AIの役割 増幅。壁打ちと下書きに徹して、本人を作業から外さない。フル自動投稿はしない 本人を外す。無人で回してよい
この資料での例 /ni・/note・/6lens・ジャーナリング LINE秘書・Vault日次バックアップ・週次ネタ発掘・NotebookLM公開AI・タスクピッカー
判断基準は一問だけ。
「これを自動化したら、本人の声が死ぬか？」
死ぬなら増幅まで。死なないなら、外してよい。

5月版の 「AIに任せたい／任せたくない」 のリストは、この一問を先に置くと、ぜんぶ同じ線から出てきます。
そして、この線は「何を自動化するか」だけじゃなく、どのAIモデルを使うかにも効いてきました。

同じ線で、AIモデルも使い分ける（2026年9月〜）

Claude には、賢さと値段の違うモデルが何種類かあります。9月に、直近30日分の呼び出しログ（5,559回）を集計して、使い分けの基準を決めました。覚え方は4語です。

モデル一言使う場面
Fable 5.1判断6視点分析、参入・撤退の判断、原因の見えない障害。ここは値段で選ばない
Opus 5創作と対話（迷ったらこれ）インタビュー、note執筆、ジャーナリング、人に届く文章
Sonnet 5作業公開後の事後処理、リサーチ、サブエージェント（6-3）、日次の取り込み
Haiku 4.5仕分け分類だけの処理

決め方は、やっぱり同じ一問。「本人が消えたら価値も消えるか？」 消えるなら（声の領域）Opus 以上、消えないなら（事務の領域）Sonnet 以下。
実測してわかったのは、重いのはモデルの値段より「毎回読ませている文脈の量」だった、ということ。これは 6-7 の司令塔ファイルの話につながります。

6.段階A：いま稼働中の"手足"

この章の目的：今この瞬間、僕がAIに任せている作業を全部見せます。

6-1. 朝の始まり：LINEに「今日の提案」が届く A NEW

場面：朝6:30、まだ布団の中。LINEに「今日の提案」が届いている。
使う仕組み：LINEの"AI秘書"（無人で動く朝の提案）＋ /good-morning（朝プラン作りのスキル）。

5月の時点では、「Macを開いて /good-morning と打つ」のが朝の始まりでした。9月からは、Macを開く前に届きます。

  • 6:30：Mac が無人で、Notion のタスク・Google カレンダー・昨日のログを集め、AI（Sonnet）に「今日の提案」を作らせて、LINE に1通送る。国試までの残り日数も、止まっている自動化の警告も、この1通に入ってくる
  • 返信で決める：提案には番号が振ってある。「2」と返信すると、Notion の「センターピン」（今日これだけは、の一点）が立つ。受け取り役は Cloudflare 上にいるので、Mac が寝ていても動く
  • Mac を開いたら：/good-morning が LINE に送った提案を読んで、続きから進める。昨日のジャーナリングやデイリーノートを読み、未完了の習慣をチェックし、インボックスの棚卸し（今日やる／置く／捨てる・最大5件）、出発時刻の計算（移動時間表から逆算して iPhone のリマインダーに「出発合図」を登録）、採用した内容を Notion・カレンダー・デイリーノートに書き込み
朝の "今日何やる？" を考える 15分が、ほぼゼロ秒になった。
AIが先に提案してきて、僕は OK / 違うを言うだけ。

※僕はスキル＝AIに対する"よく使う指示のテンプレ"を自分用にたくさん作っています（2026年9月時点で27本）。以下、/〇〇 と書いてあるものは全部それです。

6-2. note記事を書く：スキルで分業 A

note を書くワークフローは、AIに分業させています。ここは声の領域なので、AIは書き起こしと下書きまで。速さは測りません。

/ni
インタビュー専門スキル
記事を書く前に、AIが僕にインタビューしてくれる。質問は42問のライブラリから状況に合わせて3〜4問選んで投げてくる。
場面：「今日は一人芝居の話を書きたい」→ /ni 起動 → AIから問いが届く → 音声入力で答える → 素材が集まる
/note
本文執筆スキル
インタビューで集めた素材から、僕の文体（一人称「僕」・口語）で記事を書き出す。冒頭の自己紹介ブロックは固定テンプレ。書きながら、関連する過去記事を自動で探してリンク候補を出す（6月〜）。
場面：/ni の素材→ /note → 初稿 → 自分で手直しして公開
/note-publish
公開後の事後処理（自動発火）
公開した瞬間に必要な作業（前記事への「次の話リンク」追記／連載ナビの全記事同期／LINE配信文の最終形／X投稿の生成と投稿／NotebookLM公開AIへの反映／フッター整合性チェック）を担当。僕がコマンドを打つのではなく、AIが会話の流れから判断して適時発火させてくれる。
場面：「note公開した、URLはこれ」と話す → AIが自動で /note-publish を起動 → 配信文と前記事への追記が一気に整う
ChatGPT 画像生成
サムネイル制作(手作業段階)
サムネは今も、ChatGPT の画像生成機能を使っている。記事タイトルをコピーして ChatGPT のトークに貼り付け、サムネイメージを生成 → 必要なら手直しという流れ。ここは自動化しておらず、手作業の段階。
場面：記事完成 → タイトルを ChatGPT に貼る → 画像生成 → noteにアップロード

結果として、僕の声の輪郭を AI が下書きにしてくれる分業ができています。
AIが書いて僕が直す、じゃなくて、僕が話してAIが書き起こして、僕が表現を整える。同じ作業時間でも、深さと量がぜんぜん違ってきました。

※原稿ファイルの published を true にすると、公式サイトのブログにも自動で転載されます（Obsidian の変更を見張るスクリプト → GitHub → サイト再生成）。

6-4. 西野亮廣さんに"相談"する A 検索はローカル

僕は、影響を受けている方の1人として、西野亮廣さんのオンラインサロン記事（2018年〜現在の3,344本・自動取得で増え続ける）を全部、自分のMacに保存しています。
そして、RAG＝AIに自分の資料を読ませてから答えさせる仕組みを組んで、こう使う：

nishino_search.py

「集客について」「クラウドファンディング」とキーワードを投げると、関連記事を 意味的に 近いものから順に返す。単純な単語一致ではなく、意味の近さで探す。
場面：noteを書いてる途中で「西野さんが集客についてなんて言ってたっけ？」→ nishino_search.py 集客 → 該当記事を読みに行く
/nishino
西野さんに"質問する"（v2・2026年8月〜）
質問を投げると、まず Mac の中だけで動く意味検索が関連記事を絞り込み、Claude がその記事の全文を読んで「① 西野さんの声 → ② で、いっちーの場合」の二段で返す。先に"ペルソナパック"（判断軸TOP50・文体カルテ・原文の実例集）を読ませてあるので、口調と判断の癖が乗る。
場面：戦略を考えていて行き詰まった →「西野さんならどう言うか聞いてみよう」→ /nishino

6-5. 思考整理：6視点で意思決定する B寄り

  2. 西野レンズ：西野亮廣さんならどう判断するか

6-6. 第二の記憶：Screenpipe A

実例2：「関わりの非対称性」の言語化

自分の構造が言語化された瞬間、「同じ構造の人とは関われる」という抜け道も見えました。

実例3：「称賛モード／検討モード」運用合意

① 6月：無人のAIが、人間用の設定を読んでしまった

毎朝 Slack に届く日次レポートが、5月30日から「と」や朝の挨拶だけになっていた。
原因は、無人で動かすAIが、人間が使う時用の設定（対話の開始時に走る自動処理や、設定ファイルの「保存しろ」という指示）まで読み込んで、出力を乗っ取られていたこと。

決めたこと：無人で動くAIには、人間用の設定を読ませない。いま朝の提案を作るスクリプトは、設定ファイルの無い空のフォルダでAIを起動する。

② 7月：36日間、黙って止まっていた

西野さんの記事の日次取得が、6月19日を最後に36日間止まっていた。
macOS の更新後、OS がジョブの起動そのものを拒否していて、スクリプトは1バイトも実行されず、ログも残らない。ジョブの内側からは、絶対に検知できない壊れ方。

決めたこと：自動化は「外から」見張る。毎朝9:00のヘルスチェックが生まれた。全ジョブの登録状態を確認して自己修復し、前回失敗したジョブを拾い、成果物が何日更新されていないかを見て、デイリーノート・Mac通知・朝のLINEに出す。

③ 9月：AIが、自分のnote原稿を消していた

9月21日の朝、LINE の提案の冒頭に「⚠️ 止まっている自動化 7件」と出ました。東京でオーディションを受ける日で、台風でした。

調べると、7件のうち5件は前夜の Mac の電池切れ、2件はいつもの常習犯。本当に止まっていたのは別で、Vault の日次バックアップが9月17日から止まっていた（156ファイルが未保存）。

原因をたどると、AIとの対話を始めるたびに走る自動処理（フック）が、note の連載ナビを作るスクリプトを毎回・全168本に対して走らせていた。9月16日だけで23回。iCloud 上でまだ実体化していないファイルを「空」として読み、2本の原稿の本文を消していた。バックアップ側の安全装置が「原稿が縮んでいる」と検知して、止めてくれていた。

復旧は、その場でAIに頼みました。原稿299本を全部実体化 → 消えた2本を git の履歴から復元 → ナビ生成を1回だけ正しく実行（62本のリンクが復旧）→ 縮んだファイルがゼロなのを検算 → 日次バックアップを手動で実行して5日分・96ファイルを取り込み。原因のフックは撤去して、同じ処理は「note を公開した直後に1回だけ」に移しました。

自分の原稿消しちゃったりとかしていたんですけれども、そういった面でもやっぱり復旧もAIに聞けばやってくれるっていうのもあるので。そういうことがあっても、僕は任せてよかったなと、いまだに思っております。
（2026-09-21・勉強会での発言）
決めたこと：ファイルを書き戻す処理を「対話の開始」に置かない。置くなら「公開直後に1回」。そして、全部 git（履歴つきの保存）に入れておく。消えても戻せる。

3回から決めたこと（まとめ）

  1. 無人で動くAIに、人間用の設定を読ませない（空のフォルダで起動する）
  2. 自動化は「外から」見張る。ジョブの内側では検知できない壊れ方がある
  3. 書き戻す処理を「対話の開始」に置かない。置くなら「公開直後に1回」
  4. 全部 git に入れておく。消えても戻せる。5月版に書いた「記憶喪失耐性原則」が、実際に効いた
  5. 安全装置は「縮んだら止める」。止まってくれたから気づけた。止まらない自動化のほうが怖い

10.設計原則（読み飛ばし可）

この章の目的：技術寄りの裏側。仕組みづくりに興味がある人だけでOKです。5月版の①〜⑥はそのまま、⑦は更新、⑧〜⑫は4ヶ月で足したもの。

① 司令塔ファイル一極集中

判断軸は1ファイルに集約。AIごとに別々に伝えない。これで「同じ僕」が全AI対話に立つ。

② Wiki層の3オペレーション（Ingest / Query / Lint）

Ingest（取り込み）：新情報をWikiに書き込む。
Query（問い合わせ）：質問にはWikiから探して答える。
Lint（健康診断）：矛盾・古びたページを定期的にチェック。

③ 3層公開設計（L1 / L2 / L3）

L1（完全プライベート）＝自分だけ。
L2（メンバー限定）＝応援してくれる人だけ。
L3（公開）＝note（誰でも読める）。

④ HTML化判断軸

長文・構造化された分析・比較が中心の出力は HTML で書き出す（このレポートのように）。 原本は Markdown、HTML は派生ビュー。手動メンテせず、必要時に再生成。

⑤ 記憶喪失耐性原則

「いつ忘れても戻ってこれる」仕組みを優先する。ツールが変わっても、データ（Markdownファイル）が残れば仕事は続く。クラウド依存を最小化。

⑥ ソース5段階ティア

引用するソースを Tier 1（一次情報・原典）〜 Tier 5（伝聞・噂）で評価。 noteの本文には Tier 2 以上 しか使わない（SNS情報は本文に出さない）。

⑦ 火力配分 v2（強火3／中火／棚上げ）更新

5月は「強火3／中火6」でした。9月の棚卸しで、約140件の「やること・やろうとしていること」を全部並べて、強火3（俳優キャリア／年末のチャリティ公演「みんながサンタ！」／note）・中火・棚上げに振り分け直した。 ルールは3つ。棚上げには必ず振り返り日を付ける／過去日付の未完了は日曜に閉じる／声の領域は台帳に入れない。AIにも「今これは強火」を伝えて優先度を判断させる。

⑧ 質 ＞ 速度（声の領域） NEW

5月版には「note執筆が30分以内に完成する」を段階Aの卒業基準として書いていました。6月に撤回。note は声の領域なので、速度で測らない。速くなること自体を目標にしない。

⑨ 3点セット（要約＋原典＋原文ママ） NEW

別のAI（サブエージェント）に検索を任せた時、返答は要約・原典のパスと行番号・原文ママの引用の3つが揃って初めて使う。要約だけで本文を書かない。引用の時は必ず原典を開いて読む。

⑩ 自動化は外から見張る NEW

ジョブの内側では検知できない壊れ方がある（9章②）。だから、全ジョブを外から見るヘルスチェックを毎朝走らせ、結果を朝のLINEにも載せる。「動いているはず」を信じない。

⑪ 毎回読ませるものは、軽く保つ NEW

司令塔の応答ログを分離（116KB→65KB）、判断ログを設定ファイルから分離。「毎回読むファイル」が太ると、全対話が重くなる。育つファイルは、太りすぎたら分ける。

⑫ 脱・過剰指示 NEW

今のモデルは、細かい手順書や「必ず」「絶対」の連打より、目標・理由・制約で動く。命令を強くすると、やりすぎ・考えすぎが起きる。Anthropic の公式ガイドの黄金律は「文脈の薄い同僚にそのプロンプトを見せて、迷わず実行できるか」。9月、自分の設定ファイルとスキルを、この方向で見直す方針にした。

12.よくある質問（FAQ）

Q1. これ、AIに詳しくないと真似できないですよね？
全部を一気に真似する必要はありません。段階A の中の1つだけ（例：noteを書く時にAIにインタビューしてもらう）から始めるのが現実的です。僕も4年前は何も使えていませんでした。
Q2. どのAIを使ってるんですか？
メインは Claude（Anthropic社のAI）で、Claude Code というターミナル環境から使っています。2026年9月時点では、判断は Fable 5.1、創作と対話は Opus 5、作業は Sonnet 5、仕分けは Haiku 4.5 と使い分け（5章）。サブで ChatGPT（サムネ画像）、Gemini（NotebookLMの中身・デイリーノートの要約）、Mac の中で動くローカルの意味検索と文字起こし。
Q3. AIに頼りすぎて、自分で考えられなくなりませんか？
逆です。"AIに考えさせて、最後は自分で決める" という線を引いているから、考える時間が増えました。ジャーナリングは毎日やってるし、最終判断は必ず自分。AIは "並列に考えてくれる外部の脳" であって、自分の脳の代わりではない、というのが僕の使い方の核心。
Q4. 費用はかかってますか？
メインは Claude の Max プラン に課金中（のめり込み過ぎて上位プランに上げた、というのが正直なところ）。Claude の Pro プランでも、note運営1本だけ／下書き作り／小さめのWiki構築くらいなら十分回ります。
その他は Notion 学割（無料・継続中）、Google Gemini 学割（Proプラン15ヶ月無料） を活用中。Claude の利用は、無人で動く分（朝の提案・週次ネタ発掘）も含めて Max プランの定額枠で完結。従量課金に転ばないように、無人のスクリプトにはわざと API の鍵を持たせていません。ローカルAIは電気代だけ。
Q5. AIに僕の個人情報を全部渡して大丈夫？
ここは慎重に設計しています。機密性が高い情報はローカルAI（クラウドに送らないAI）で処理／公開しないファイルは Vault 内に保存し、note には出さない（3層公開設計）／SNS情報や他人のプライバシーは AI に学習させない。ボイスメモの文字起こしと分類も、クラウドには送りません。
Q6. 「AI使ってる」と「AI任せ」の違いは？
僕の中の線引きは「誰の声で書いてあるか」です。AIに下書きさせても、最終的に 「いっちーの声」で公開できる状態 まで自分が編集する。声を譲った瞬間にそれは "AI任せ" で、僕の表現じゃなくなる。5章の「声の領域／事務の領域」は、この線引きを仕組みにしたものです。
Q7. 真似してみたい、どこから始めればいい？
まず 「司令塔ファイル"もどき"」をテキストで1枚作る ことをおすすめします。「私は何者か／何を目指してるか／何を譲れないか」を箇条書きで1ページ。それを毎回 ChatGPT / Claude の最初に貼り付けるだけで、返ってくる答えの精度が劇的に変わります。
Q8. 自動化が壊れたらどうしてるの？ NEW
4ヶ月で3回壊れました（9章）。いまは毎朝9:00のヘルスチェックが全ジョブを外から見張って、止まっていれば朝のLINEの冒頭に「⚠️」が出ます。直すのもAIとの対話。原因の調査から復旧の手順、再発防止の設計まで、その場で頼みます。
Q9. スマホからも使えるの？ NEW
日常の入口は LINE です。朝の提案が届く、番号で返す、夜の振り返り質問が届く、出発の合図が鳴る、ボイスメモが文字になる。Claude Code 自体も、スマホから Mac を遠隔で動かすことも、Mac なしでクラウド上で動かすこともできます（Vault を GitHub に置いてあるので）。
Q10. AIモデルの使い分けって、そこまで必要？ NEW
迷ったら Opus で十分です。使い分けの一問は「本人が消えたら価値も消えるか？」。消えない作業（同期・分類・事後処理）を安いモデルに回すと、値段も速度も楽になる。ただ、実測してわかったのは、重いのはモデルより「毎回読ませている文脈の量」でした（5章・6-7）。
Q11. AIに「必ず〜して」と強く書けば言うことを聞く？ NEW
今のモデルは、逆効果になることがあります。細かい手順書や「必ず」「絶対」の連打より、目標・理由・制約を書いたほうが動く。Anthropic の公式ガイドの黄金律は「文脈の薄い同僚にそのプロンプトを見せて、迷わず実行できるか」。僕も9月に、自分の設定ファイルをこの方向で見直す方針にしました（10章⑫）。

13.用語集

この章の目的：本文に出てきた言葉を、まとめてやさしく解説。気になったものだけ開いて読んでください。

AI業界の言葉

AI（人工知能）
広い意味では「人間っぽい判断ができるプログラム」全部。この資料では ChatGPTやClaudeのような、文章で対話するAI を指しています。
LLM（大規模言語モデル）
Large Language Model の略。大量の文章を学習して、次に来る言葉を予測する仕組み。ChatGPT・Claude・Geminiの正体はこれ。
プロンプト
AIへの指示文。「〇〇について教えて」「△△風に書いて」のような"頼みごとの言葉"。プロンプトの書き方で結果が大きく変わる。
コンテキスト
AIに渡している情報の塊。"AIに今読ませているもの全部"と思えばOK。長く話してると古い話を忘れていく仕組みでもある。太ると重くなる（6-7）。
スキル／カスタムコマンド
AIに対する"よく使う指示のテンプレ"。/note と打つだけで「いつものnote執筆のお願い」が一気に発動する、みたいな仕組み。
サブエージェント
メインのAIが、別のAIを"部下"として起動して仕事を振る仕組み。僕の場合は絞り込み係。安いモデルに重い検索をさせ、精読と引用はメインが原典を開いてやる。
RAG（検索拡張生成）
Retrieval-Augmented Generation の略。AIに自分の資料を読ませてから答えさせる仕組み。一般知識じゃなく、自分のメモから答えてほしい時に使う。
embedding（埋め込みベクトル）／意味検索
文章を「意味の点」に変換する技術。"集客" と "お客さんを集める" は別の単語だけど、意味的には近い——を判定できるようになる。
ローカルAI／ローカルLLM／Ollama
クラウドに送らず、自分のパソコンの中だけで動くAI。プライバシーが守れる／オフラインで動く／費用ゼロ、が利点。性能はクラウド最強モデルよりは劣る。Ollama（オラマ）は、それを Mac で動かすための土台ソフト。
Markdown（マークダウン）
記号で見出しや太字を表現できる、軽量なテキスト形式。# で見出し、**太字** で太字、みたいな。ファイルはただのテキスト。
frontmatter（フロントマター）
Markdownファイルの冒頭に書く"メタデータ"。タイトル・日付・公開状態などをまとめて書く場所。
Anthropic（アンソロピック）／Claude
Claude を作っているAI企業。元 OpenAI のメンバーが創業。Claude はその主力AI製品（このレポートを書くのを手伝ってくれている AI 本体）。
Claude Code（クロード・コード）
Anthropic が出している"ターミナルで動くClaude"。ファイル編集・コード実行・自作スキル発火ができる開発者向けツール。
Fable／Opus／Sonnet／Haiku
Claude のモデルの名前。上から順に、賢くて高い→速くて安い。僕は 判断／創作と対話／作業／仕分け で使い分けている（5章）。
フック（hook）
「AIとの対話が始まった時」「ファイルを保存した時」のようなきっかけに合わせて自動で走る処理。便利だが、置き場所を間違えると9章③のようなことが起きる。
git／GitHub／PR
git はファイルの変更履歴を全部残す仕組み。GitHub はそれをクラウドに置く場所。PR（プルリクエスト）は「この変更を取り込んでください」というひとまとまり。僕の Vault は毎朝7:05に自動で PR が作られ、取り込まれる。消えた原稿もここから戻せた。
Cloudflare Workers
小さなプログラムをクラウドに置いて、自分のパソコンが寝ていても動かせる仕組み。LINE の返信を受け取って Notion に書く係が、ここにいる。
Whisper（文字起こしAI）
音声を文字にするAI。僕は Mac の中で動く版を使っていて、ボイスメモをクラウドに送らずに文字起こししている。
NotebookLM（ノートブック・エルエム）
Googleが作った"自分の資料を学習させて対話できるAIノート"。僕は note 記事を全部読ませて「いっちー専用AI」を作っています。
LaunchAgent（ローンチエージェント）
macOS の標準機能で、「毎日何時に自動でこれを実行する」を仕込む仕組み。タイマー予約の上位互換。いま30本前後（6-10）。
Hammerspoon（ハンマースプーン）
Mac の操作をキー1つで自動化するためのソフト。⌘⌥T のタスクピッカーと、画面右上の「いま取り組んでいるタスク」表示はこれで作っている。
Obsidian（オブシディアン）
Markdownでメモが書ける、フォルダベースのノートアプリ。データは全部自分のパソコンに残る。リンク機能でメモ同士をつなげられる。
Notion（ノーション）
データベース機能つきのノートアプリ。表・カレンダー・ガントチャートなど色んな"見せ方"でメモを扱える。
Screenpipe（スクリーンパイプ）
画面をずっと録画＆文字起こしして、自分専用の"記憶倉庫"を作るソフト。「3日前に見たYouTube」を後から検索できる。

いっちー用語（独自に作った言葉）

声の領域／事務の領域 NEW
本人が消えたら価値も消える領域（声）と、誰がやっても同じ領域（事務）。声はAIが増幅まで、事務は本人を外してよい。判断の一問は「これを自動化したら、本人の声が死ぬか？」（5章）。
司令塔ファイル
AI対話のすべての起点になる1枚のMarkdownファイル。「いっちーは何者か」「目指してる地点」「譲れない信念」を集約。AIは毎回これを読んでから返答する。
応答ログ NEW
AIとの対話から拾った本人の言葉を、原文ママで時系列に溜める別ファイル。司令塔が太りすぎたので9月に分離した（6-7）。
Wiki層（AI第二の脳）
Karpathy 式と呼ばれる、"AIが新規ページを書き、僕が監修する" 知識ベース。気づき・概念・人物・分析をぜんぶここに蓄積。
段階A／B／C（AI活用の3段階）
A＝タスク代行（手足）／B＝脳の拡張（壁打ち）／C＝人生のパートナー。AIとの関わり方の進化モデル。いまは A 中心、B は走っている、C は一歩目が動いた。
3層公開設計（L1 / L2 / L3）
コンテンツを3つの公開レイヤーに分ける設計。L1＝自分だけ／L2＝応援者だけ／L3＝誰でも。それぞれ別のツールで運用。
5層モデル（コア欲望）
自分の欲望を浅い→深いで5段階に整理したフレーム。第1層（公的目標：カンヌ主演男優賞）／第2層（信念：演劇は世界を平和にする）／第3層（職業の核：再現性ある芝居）／第4層（生き方の核：自分の心のままに生きたい）／第5層（探索中）。
6lens（6視点並列分析）
意思決定の時、6つの目線（俳優／西野／観客／コア欲望／信念／第一原理）で並列に検討するスキル。/6lens で発火。
火力配分 v2（強火3／中火／棚上げ）
同時並行の戦線を、強火3つ（全力）・中火（外の声を聞ける余白）・棚上げ（必ず振り返り日つき）に振り分ける温度管理。5月は「強火3／中火6」。9月の棚卸しで組み直した。
開いた輪／閉じる儀式 NEW
開いた輪＝始めたまま終わっていない「やること・やろうとしていること」。9月に約140件を全部並べた。閉じる儀式＝毎週日曜21時の週次レビューで、輪を閉じるか、日付をつけて棚に上げる。
センターピン NEW
「今日これだけは」の一点。朝の提案に番号で返信すると Notion に立つ。倒せば他のピンも倒れる、ボウリングの先頭ピンのイメージ。
3点セット NEW
サブエージェントの返答に必ず求める3つ。要約＋原典のパスと行番号＋原文ママの引用。揃っていない返答は使わない。
ヘルスチェック（外から見張る） NEW
毎朝9:00に全自動化ジョブを外から点検する仕組み。登録状態の自己修復・失敗の検知・成果物の鮮度チェック。7月の「36日間サイレント停止」から生まれた（9章）。
LINE秘書 NEW
LINE の公式アカウントの仕組みを使った、自分専用のAI窓口。朝の提案・夜の振り返り・自動化の警告がここに届き、番号の返信でセンターピンが立つ。
ソース5段階ティア
引用ソースの信頼度を Tier 1（一次情報）〜 Tier 5（伝聞） で評価する内部ルール。noteの本文には Tier 2 以上しか使わない。
記憶喪失耐性原則
「いつ忘れても戻ってこれる」を最優先する設計思想。ツールが変わってもデータが残るように、すべての記録はプレーンなMarkdownで持つ。9月、消えた原稿が git から戻って、実際に効いた。
HTML化判断軸
どんな出力をHTMLにするか／Markdownのままにするかの判断基準。長文・比較・構造化された分析は HTML、原本は Markdown。このレポートも HTML 化対象。
ストック型／フロー型（note記事の分類）
ストック型＝時間が経っても読まれる記事。フロー型＝今日のリアルタイム記事。1700万件のnote追跡調査ベース。各記事を書く前にどちらか判定する。
信念候補
「まだ確定じゃない信念」を1〜4週間"熟成"させて、本人が再確認したら正式信念に昇格させる仕組み。熟成期限が来たらAIが「これ昇格させる？」と聞いてくる。7月に最初の1件が昇格した。
セカンドブレイン
"頭の外に作る、もう1つの脳"という考え方。タスク・気づき・進捗を全部 Notion に書き出して、頭の中を空にする。「今やっていること」が画面右上に常時表示される仕組みで、シングルタスクに引き戻す効果も狙っている。
